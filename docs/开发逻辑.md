# SDK 开发逻辑：转发 → 监视 → 回传

SDK 只整理已有系统接口。发送命令代表已转发；`success` 代表观察到完成状态；`disarmed` 代表观察到已上锁。三者分别判断。

## 1. 程序只分三层

| 文件 | 做什么 | 主要入口 |
| --- | --- | --- |
| [config.cpp](../src/config.cpp) / [YAML](../config/control_sdk.yaml) | 读通信配置、到达默认值并校验 | `Config::load()` |
| [control_sdk.cpp](../src/control_sdk.cpp) | 发布命令、订阅并缓存原始状态 | `takeoff()`、`land()`、`returnHome()`、`resume()`、`goTo()`、各订阅回调 |
| [flight_control_node.cpp](../src/flight_control_node.cpp) | 检查请求、互斥、映射反馈和结果 | `onTakeoff/onLand/onGoto/onReturn`、对应 update/cancel 方法 |

飞行与定位状态/Action 使用默认单线程 `ros::spin()`；新增 LoadMap 的文件读取与后端确认在独立服务队列执行，详情见 [定位开发流程](README_定位与点云加载.md)。状态回调触发完成判断；反馈 WallTimer 只定时发布反馈；另一个单次 WallTimer 在 Continue 后 0.2 s 发送 Goto 目标。`setStateCallback()` 仅接收 DroneState，`setUpdateCallback()` 接收 DroneState、State、ExtendedState、Odometry 更新通知。高度由反馈发布时读取。

直接调用 C++ `ControlSdk::takeoff()/land()/returnHome()/resume()/goTo()` 只转发消息；需要准入、任务互斥、取消和结果时使用 Action。保留 `ControlSdk(nh, drone_id)` 构造接口。

## 2. ROS 消息对应表

下表名称是默认配置；所有话题均可配置或 remap。

| 方向 | 话题 / 消息 | 使用字段 | SDK 用途 |
| --- | --- | --- | --- |
| 发布 | `/control` · `controller_msgs/cmd` | `header.stamp`、`cmd` | 一次发送 `1` 起飞、`2` 降落、`3` 返航或 `4` Continue；不 latch、不重发 |
| 发布 | `/goal_with_id` · `quadrotor_msgs/GoalSet` | `drone_id`、`goal[3]` | 原生 xyz 直接转发；无 Header、速度字段或任务 ID |
| 订阅 | `/drone_{id}_state` · `controller_msgs/DroneState` | `header.stamp`、`tookoff`、`landed`、`reached`、`returned` | 起降完成、阶段映射、Goto 到达和 Return 完成依据 |
| 订阅 | `/mavros/state` · `mavros_msgs/State` | `header.stamp`、`connected`、`armed` | 连接准入、四个飞行 Action 完成时的连接检查、独立上锁报告 |
| 订阅 | `/mavros/extended_state` · `mavros_msgs/ExtendedState` | `header.stamp`、`landed_state` | 补充控制器丢失的起降过渡态，确认真实着地 |
| 订阅 | `/mavros/local_position/odom` · `nav_msgs/Odometry` | `header.stamp`、`pose.pose.position`、`twist.twist.linear` | 起飞相对高度；Goto 当前速度模长 |
| 订阅 | `/drone_{id}_visual_slam/odom` · `nav_msgs/Odometry` | `header.frame_id/stamp`、`pose.pose.position` | 与 Planner 同源；Goto 距离和到达计时 |
| 订阅 | `/mavros/altitude` · `mavros_msgs/Altitude` | `bottom_clearance` | 降落时报告机体下方净空 |

`DroneState` 由 `Spikive-Planner-SDK/src/planner/drone_control/src/px4ctrl.cpp` 发布至 `/drone_state`，再由 同目录的 `launch/px4ctrl.launch` 转发。它是控制器的执行状态，并非 SDK 自算的规划状态。

## 3. 请求流程

```mermaid
flowchart TD
  A[收到起飞 / 降落 / 返航请求] --> B{本节点已有活动任务？}
  B -->|是| R[拒绝：不发送命令]
  B -->|否| C{连接、状态、订阅者、时间及动作条件满足？}
  C -->|否| R
  C -->|是| D[接受请求：转发一次命令；起飞另记录高度基准]
  D --> E[记录命令时间，监视后续状态]
  E --> F{收到本任务取消？}
  F -->|是| X[返回取消，释放任务槽；飞机控制不变]
  F -->|否| G{存在命令之后的完成证据？}
  G -->|否| H[按现有状态更新反馈]
  H --> E
  G -->|是| I[发布最终反馈与成功结果，释放任务槽]
```

| 检查 | 条件 / 结果 |
| --- | --- |
| 公共准入 | 收到 DroneState；MAVROS 已连接；ExtendedState 为已知状态 1–4；`/control` 有订阅者；ROS 时间有效。否则 `12`。 |
| 起飞准入 | `tookoff=false && landed=true` 且 MAVROS `ON_GROUND`；空中或起降过渡态返回 `7`。里程计 z 必须有限，否则 `4`。 |
| 降落准入 | MAVROS 已为 `ON_GROUND` 时拒绝并返回 `6`；不以 `tookoff=false` 判断未起飞，不要求里程计或净空测量。 |
| Goto 准入 | 公共准入之外，要求 `/goal_with_id` 有订阅者、MAVROS `IN_AIR`、配置坐标系内、带非零时间戳的导航里程计有限 xyz；否则 `12/6/4`。所有请求字段必须有限（`19`）；原生目标 z 低于 -0.1 时拒绝（`20`，后端不支持）。 |
| Return 准入 | 公共准入之外，要求 `/goal_with_id` 有订阅者（否则 `12`）、MAVROS `IN_AIR`（否则 `6`）；已有 `returned=true` 拒绝 `12`，避免重用完成标志。不计算距离，不额外依赖里程计。 |
| 互斥 / 取消 | 忙时拒绝 `21`；取消当前 Action 返回 `3`，仅释放跟踪任务。旧任务的取消不影响新任务。 |
| 完成时间 | 完成证据的 `header.stamp > command_stamp`；零时间戳和请求前缓存不能完成任务。 |

公共准入是通信和状态检查，不代表完整的飞行自检。时间戳只关联先后，不是控制器 ACK；已有协议没有任务 ID。无任务超时、状态年龄策略或自动重试，断流时缓存可能保留，不能据此声称数据仍实时。互斥只覆盖本节点四个飞行 Action。

### Goto 流程

```mermaid
flowchart TD
  A[Goto 请求：原生局部 xyz] --> B{互斥与准入通过？}
  B -->|否| R[拒绝，不发命令]
  B -->|是| C[接受；转发 cmd=4 Continue]
  C --> D[单次定时器等待 0.2 s]
  D --> E{连接、订阅者和空中条件仍满足？}
  E -->|否| X[中止跟踪；Continue 已发出]
  E -->|是| F[原样发布 GoalSet；记录本地发送时间]
  F --> G[监视新 DroneState 和导航里程计]
  G --> H{reached 且距离满足？}
  H -->|否| I[state=1；清零稳定计时]
  I --> G
  H -->|是| J[state=3；以两个样本的较早时间累计稳定时长]
  J --> K{达到 stable_time？}
  K -->|否| G
  K -->|是| L[state=4；success=true；释放任务槽]
```

- `position=[x,y,z]` 原样转给 GoalSet；与 Planner、导航里程计共用原生 world 坐标。按用户要求覆盖 PDF 的 NED 注释，不交换轴或反转 z，不添加 TF。目标是绝对局部坐标。
- 目标发送前保留 WayPoint 的 Continue → 0.2 s → 目标顺序。FlightManager 切换到 Continue 时会发送当前位置；现有协议无 ACK，这个延迟不能保证所有负载下的处理顺序。
- 距离使用目标减 `/drone_{id}_visual_slam/odom` xyz 的三维/XY 范数；速度用 MAVROS 线速度模长（SLAM 未填写 twist）。导航里程计 frame 必须等于 `frames/world`，无效时距离为 NaN、不回退到 MAVROS 位置。控制器 `reached` 只检查 XY，所以追加 PDF 要求的两个距离和稳定时长，缺失状态才自己计算。
- `arrival_total_dist / arrival_horiz_dist / stable_time` 正值按请求，`<=0` 使用 Config 默认 `0.30 m / 0.25 m / 1.0 s`，不改写后端参数。
- 成功要求新 `reached && !landed`、新导航里程计、连接与 `IN_AIR`、两个距离阈值及稳定时长。稳定计时取两个消息时间戳较小者，条件失去或时间倒退则重计；断流期间不靠反馈定时器累计时间。没有数据年龄规则，不能证明采样空隙内的状态。
- `state=3 HOLDING` 表示观察到到达条件并等待稳定，不是发送了悬停命令；缺少独立避障状态，不输出 `state=2`。结果 `final_distance` 为最新有效三维距离；位置无效或拒绝请求为 NaN。
- 取消结束跟踪，停止尚未触发的目标发送定时器；已发送的 Continue/GoalSet 不撤回，不额外发送停止或悬停。

### Return 流程

```mermaid
flowchart TD
  A[Return 请求] --> B{互斥、连接、订阅、IN_AIR 且 returned=false？}
  B -->|否| R[拒绝；不发命令]
  B -->|是| C[接受：phase=1；仅转发 cmd=3]
  C --> D[FlightManager 发布既有返航点；Planner 和 px4ctrl 执行]
  C --> E[SDK 监视命令后的状态]
  E --> F{收到新的 returned=false？}
  F -->|否| E
  F -->|是| G[phase=2；记录 false 样本时间]
  G --> H{更晚的 returned=true 且未着地、连接有效、新 IN_AIR？}
  H -->|否| E
  H -->|是| I[phase=4、progress=1；返回 success=true]
  E -->|客户端取消| X[只结束跟踪；飞机控制不变]
```

- `ControlSdk::returnHome()` 仅发布一次 `cmd=3`，不发 Continue、GoalSet 或降落。返航点由 FlightManager 决定，SDK 不读写其参数，不新增 home 配置。
- FlightManager 的 `init_x/init_y/init_z` 必须与现有坐标一致；其可选 `/autoloc/initial_pose` 只更新 XY。SDK 的起飞起点、Relocalize 初值不会自动改变它。重定位后的地图坐标与 MAVROS 本地坐标也不由 SDK 对齐。
- `px4ctrl` 的轨迹分支使用 XY `< reach_dist` 设置 `is_returned`；发布 `returned` 时还要求该标志持续至少 3 s 且 `return_triggered=true`。SDK 直接消费此状态，不另算到达距离、稳定时间或航向。
- `is_returned` 有保留旧值的路径，所以仅过滤旧时间戳不够。接受请求时拒绝已有 `returned=true`；发送后以 `return_pending_stamp_` 记录新的 false，只有时间更晚的 true 才可完成，再补查 `!landed` 和新的 MAVROS `IN_AIR`、连接。此过滤仍不能证明外部发布者没有替换目标。
- 接受后为 PRECHECK；命令后收到 false 为 RETURNING，只表示跟踪中，不证明飞机已经朝返航点运动。没有独立稳定阶段、剩余距离或百分比来源，所以只输出阶段 1/2/4 与进度 0/1。
- FlightManager 只在命令码变化时处理 Return，连续 cmd=3 不重新派发。取消后重发只能观察仍在进行的返航；缺少新 false→true 会等待。SDK 不替后端清标志或插入控制命令。返航成功后如需降落，另调用 Land。

## 4. Action 字段对应表

Takeoff、Land、Goto 保持 PDF 字段类型与顺序；Return 的 PDF 只有接口名，其字段为 SDK 补充定义。本表解释当前含义。

| 输出字段 | 来源 / 计算 | 条件 |
| --- | --- | --- |
| Takeoff `success` | `DroneState.tookoff` | 本次命令之后为 true 且 MAVROS 连接有效时成功；原控制器条件为 `takeoff_triggered && is_in_air && abs(hover_height-position_z)<0.1` |
| Takeoff `phase` | 既有状态映射 | 接受时 `1 PRECHECK`；新控制器状态 `landed=false`，或新 MAVROS 状态 `TAKEOFF/IN_AIR` 时为 `2 CLIMBING`；成功 `4 DONE`。完成与阶段更新均需新 DroneState 和有效连接；其余保持 PRECHECK。无独立稳定状态，不输出 `3`。 |
| Takeoff `current_altitude` | MAVROS `z - 本次命令前的 z` | 只作反馈；收到无效 z 时输出 `NaN` |
| Takeoff `progress` | 完成状态 | 未完成 `0`，完成 `1` |
| Land `success` | `DroneState.landed && ExtendedState.ON_GROUND` | 两个状态均在命令之后，且 MAVROS 当前连接有效 |
| Land `phase` | 既有状态映射 | 接受后及 `IN_AIR/LANDING` 为 `1 DESCENDING`；成功时 `3 TOUCHDOWN`，同时确认上锁则 `4 DISARMED`。没有独立触地检测信号，不输出 `2`。 |
| Land `height` | MAVROS `Altitude.bottom_clearance` | 有限且非负时直接反馈；未收到或无效时 `NaN`；不参与成功判定 |
| Land `disarmed` | MAVROS `State` | 新的 `connected=true && armed=false` 才为 true；false 表示未确认。拒绝请求时按已有非零时间戳的状态报告。 |
| Return `success` | 新 `DroneState.returned` | 命令后先 false 再更晚 true，同时 `!landed`、MAVROS 连接和新 IN_AIR；不自动降落 |
| Return `phase / progress` | 跟踪状态 | 初始 `1/0`；新 false 时 `2/0`；成功 `4/1` |
| 四个飞行 Action 的 `error_code / message` | 适配结果 | `0` 成功；`3/4/6/7/12/19/20/21` 见请求表；message 解释原因 |

Land 的初始 DESCENDING 表示开始跟踪降落，并不是速度测量确认。降落在确认着地时返回成功，`disarmed` 是该时刻的快照，不等待后续上锁。取消返回 `success=false`，不改变飞行状态。

Takeoff/Land 输入的 `target_altitude/climb_speed/descend_speed/timeout` 全部预留，任何值均忽略并写请求日志；Return 的 `timeout` 同样处理。Goto 的 `speed/timeout` 也预留，但仍检查有限值。实际高度和速度仍由现有后端决定，详见 [README 对应表](../README.md)。

## 5. 逻辑核对结论

| 核对项 | 处理 |
| --- | --- |
| 控制器把 `TAKEOFF/LANDING/UNDEFINED` 也归为 `landed=true` | 起飞准入补查 MAVROS `ON_GROUND`；降落成功必须双状态确认；MAVROS `TAKEOFF` 可补充起飞阶段。 |
| `LANDING` 仅表示正在降落 | 映射为 DESCENDING，不伪造 GROUND_DETECT。 |
| 无效里程计曾保留旧高度反馈 | 改为 `NaN`；断流保留缓存仍属未实现的状态年龄策略。 |
| 已发送命令与实际执行 | SDK 不输出 setpoint、不调用 MAVROS 控制服务；只有状态证据能完成任务。 |
| `disarm()` 只有定义没有调用 | SDK 只读 `armed`，不承诺自动上锁。 |
| Planner 地面高度与 MAVROS 高度 | `/ground_height_measurement` 是轨迹前方地面坐标 z，不是当前下方净空；不用于 Land.height。 |
| 原控制器的降落门控 | LANDING 会令 `is_in_air=false`，而下降分支要求 `landing_triggered && is_in_air`。该后端限制保留，SDK 只监视，不接管或修正飞行控制。 |
| Goto 与 Planner 的协议依赖 | 依赖 `/control` 的 cmd=4、GoalSet 和 DroneState 的既有语义；不是零耦合。SDK 不链接 Planner/px4ctrl 的实现，不调用 MAVROS 控制 Service 或写飞控参数。 |
| Goto 后端限制 | Planner 忽略 z<-0.1；地形跟随可能改写 z；px4ctrl 只在 XY 改变时更新到达过程。SDK 按原请求监视距离，可能持续等待，不代修后端。 |
| Return 后端限制 | 返航点属 FlightManager；returned 仅体现既有 XY/标志持续逻辑，可能保留旧值；连续 cmd=3 不重新发布目标。SDK 检查 false→true，不新增返航算法或控制命令。 |
| 坐标来源 | 地图、初值按 WayPoint 的 world；Goto 读取 Planner 同源定位里程计；起飞高度仍来自 MAVROS。不将后端 map 回显标签当成 SDK 输入约定，不自动对齐飞控坐标。 |
| 匹配成功 | 使用 SLAM localized，不二次比较 JSON 舍入后的 fitness 与 threshold；保留本轮开始/新变换检查。 |
| Config / 构建 | 默认值 → 私有参数；launch 先加载 YAML 再设置 id。校验 id 在 0–32767、频率与到达默认值有限正值、名称非空、五个 Action 名不同（含 Relocalize），节点同时检查 remap 后名称；安装库、头文件、节点、Action、launch、config、文档。 |

验收只做 PDF 字段核对和 Noetic 编译链接，不执行飞行测试。后续扩展保持“现有状态优先，缺失信息才补 MAVROS；描述 + 对应表 + 流程图”的结构，不增加独立控制逻辑。


## 6. 地图与定位适配

| 文件 | 职责 |
| --- | --- |
| `localization_io.cpp` | 校验并读取 PCD/MD5，校验初值 frame/位姿，解析 SLAM JSON 状态；不运行配准算法 |
| `localization_sdk.cpp` | LoadMap Service、Relocalize Action、10 Hz 定位状态、后端回显确认及结果转换 |
| `LoadMap.srv` | PDF V1.1 原定义 |
| `relocalize.action` / `LocalizationStatus.msg` | SDK 补充协议，字段和成功条件见定位 README |

定位只通过已有 ROS 话题与 SLAM 交互，不写 SLAM 参数，不修改匹配算法或 MAVROS 输出。LoadMap 与 Relocalize 共用定位任务槽，与四个飞行 Action 的任务槽分开；Service 回调线程共享状态用互斥保护。全流程、消息对照和命令见 [定位与点云加载](README_定位与点云加载.md)。

本轮坐标来源、协议边界和离线验证见 [坐标对齐与验证](README_坐标对齐与验证.md)。
